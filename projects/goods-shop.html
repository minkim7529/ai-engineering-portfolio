PROJECT · goods-shop

Goods Shop 웹 프로젝트

카카오톡 이모티콘 캐릭터 굿즈를 온라인으로 판매하는 Java 웹 쇼핑몰

GitHub 저장소 (발표자료) → 개인 개발 · 수업 과제
  • Java
  • MVC 패턴
  • Database 연동
  • 약 1개월 (2024.8.1~8.30)

개요

대구대학교 AI학과 "웹 프로그래밍" 수업 과제로, 약 한 달간 혼자 기획·설계·구현한 Java 웹 쇼핑몰입니다. 좋아하는 카카오톡 이모티콘 관련 굿즈가 오프라인으로만 판매되는 것을 보고, 온라인 판매 사이트를 직접 만들어보자는 아이디어에서 시작했습니다.

진행 과정

주제 선정(8/1) → 개발 환경 구축(8/5) → 메인/회원가입(8/8~8/9) → 로그인·게시판(8/12~8/16) → 챗봇·굿즈 리스트(8/19~8/23) → PPT 및 기능 점검(8/26~8/29) → 발표(8/30) 순서로 약 한 달간 진행했습니다.

주요 기능

  • 회원가입/로그인 — 데이터베이스 연동, 중복 가입 방지
  • 굿즈 리스트 / 홈페이지
  • 장바구니 — 수량 조절, 합계 자동 계산
  • 게시판 — 글 작성/조회/삭제, 페이지네이션
  • 리뷰 작성 — 닉네임/내용/이미지 업로드
  • 챗봇 프로토타입 — 버튼 기반 FAQ + 1:1 상담 연결(규칙 기반)

설계 — MVC 구조

REVIEW · USER · CART_ITEM · LIST(굿즈) 4개 테이블로 ERD를 설계하고, HomeController가 ReviewService·CartService를 통해 홈/굿즈/장바구니/리뷰/챗봇 페이지를 처리하는 MVC 구조로 만들었습니다. 인증은 UserController + UserService + UserRepository로 별도 분리해 책임을 나눴습니다.

느낀 점

회원가입부터 장바구니, 게시판, 챗봇 프로토타입까지 사이트 전체를 혼자 설계하고 구현하면서, 화면 하나를 완성하는 것보다 REVIEW·USER· CART_ITEM·LIST 테이블 구조와 컨트롤러-서비스 책임 분리처럼 전체 구조를 먼저 잡는 게 이후 작업 속도를 크게 좌우한다는 걸 체감했습니다. 인증 로직을 UserController/ UserService/UserRepository로 별도 분리해둔 덕분에, 장바구니나 리뷰 기능을 추가할 때 로그인 관련 코드를 거의 다시 들여다볼 필요가 없었습니다.

문제 해결

한 달이라는 일정 안에서 챗봇까지 넣기로 하면서, LLM 연동 같은 복잡한 방식은 시간상 무리라고 판단했습니다. 대신 자주 나올 법한 질문을 버튼 기반 FAQ로 먼저 걸러내고, 해결되지 않는 경우만 1:1 상담으로 연결되는 규칙 기반 구조로 범위를 좁혀 정해진 일정 안에 실제로 동작하는 기능으로 완성했습니다.
