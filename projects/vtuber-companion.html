개요

Open-LLM-VTuber는 LLM·ASR·TTS·Live2D를 묶어 음성으로 대화하는 오픈소스 데스크톱 컴패니언 프로젝트입니다. 완전히 무료로, 로컬에서 돌아가는 컴패니언을 만드는 것이 목표였기 때문에 LLM 백엔드를 Ollama(로컬)와 Gemini(무료 티어 클라우드) 사이에서 직접 바꿔가며 같은 페르소나 프롬프트로 답변 품질을 비교하는 실험부터 시작했습니다.

진행 과정 — 모델 백엔드 비교 실험

같은 캐릭터 프롬프트를 그대로 둔 채 LLM만 바꿔 끼우면서 답변 품질을 비교했습니다.

  • Ollama(로컬 7B급 모델) — 프롬프트를 여러 차례 고쳐써도 답변의 정확도와 자연스러움이 일정 수준 이상 올라가지 않았습니다. 뒤에 정리한 정체성 역전·한자 혼입·반복 발화 같은 실패 유형들도 결국 이 한계에서 비롯된 증상이었습니다.
  • Gemini(클라우드 API) — 똑같은 프롬프트에서 훨씬 정확하고 자연스러운 답변을 생성했습니다. 다만 무료 토큰/요청 한도 때문에 장시간 반복 실험을 이어가긴 어려웠습니다.
결론 — Open-LLM-VTuber 같은 오케스트레이션 레이어의 완성도는 결국 그 아래에서 돌아가는 LLM 자체의 능력에 상한선이 걸린다는 것을 직접 확인했습니다. 이후에 만든 프롬프트 개선·정규식 필터들은 이 상한선 안에서 품질을 최대한 끌어올리는 역할이지, 기반 모델의 한계 자체를 없애주지는 못합니다. 같은 이유로 TTS 엔진도 무료 티어 모델(Edge TTS)로 교체하는 실험을 성공적으로 마쳤고, 이 구조라면 나중에 원하는 보이스 모델을 직접 커스텀해서 얹을 수 있다는 것도 확인했습니다.

주요 기능 — 그 위에서 직접 만든 것

  • Ollama 네이티브 백엔드 (ollama_llm.py, 신규 252줄) — OpenAI 호환 엔드포인트 대신 Ollama의 네이티브 /api/chat를 직접 사용해 think:false로 Qwen3 계열의 추론 트레이스를 확실히 꺼서 답변 하나당 150여 토큰을 절약했습니다. 스트리밍 파싱, 비전 모델용 이미지 다운스케일(최대 1024px), 모델 preload/keep-alive/unload 생명주기 관리, 툴 호출 시 OpenAI 호환 경로로의 폴백까지 포함합니다.
  • 발화 다양성 엔진 — 능동 발화(proactive-speak) 트리거마다 5가지 상황 변형 중 직전과 겹치지 않는 것을 골라 지시하고, 클라이언트별 최근 발화 3개를 기억해 "방금 한 말과 다르게 말해줘"를 프롬프트에 실시간으로 주입하는 구조를 만들었습니다.
  • 정체성 역전 가드 — 캐릭터가 스스로를 "오빠"라 칭하거나 유저를 "여동생"이라 부르는 등 고정된 관계 설정이 뒤집히는 현상을 정규식으로 문장 단위에서 잡아내 안전한 대사로 치환하는 데코레이터를 작성했습니다.
  • 출력 정제 파이프라인 — 양자화 모델이 간헐적으로 흘리는 한자/전각 문자, 금지된 이모지를 스트림 청크 단위로 제거하고, <think> 태그가 청크 경계에서 잘려도 안전하게 걸러내는 버퍼 기반 스트리퍼를 구현했습니다.

# 아티팩트라 프롬프트로는 막을 수 없음 - 한자(CJK)·전각 문자 대역을
# 무조건 제거해도 안전함
HANZI_RE = re.compile(r"[一-鿿　-〿＀-￯]+")

EMOJI_RE = re.compile(

    "\U0000fe0f"

def _downscale_base64_image(b64_data: str) -> str:
    """
    이미지(예: 1920x1080 전체 화면 캡처)의 긴 변을 최대
    MAX_IMAGE_DIMENSION(1024px)로 줄인다. 비전 모델은 원본
    해상도로 이미지를 처리하므로, 풀HD 스크린샷은 인코딩에
    시간이 오래 걸린다 - 화면을 설명하기에 충분한 디테일은
    유지하면서 처리 시간을 크게 줄인다.
    """
    try:
        raw = base64.b64decode(b64_data)
        with Image.open(io.BytesIO(raw)) as img:
            if max(img.size) <= MAX_IMAGE_DIMENSION:
                return b64_data
            img = img.convert("RGB")
            img.thumbnail((MAX_IMAGE_DIMENSION, MAX_IMAGE_DIMENSION))
            buffer = io.BytesIO()
            img.save(buffer, format="JPEG", quality=85)
            return base64.b64encode(buffer.getvalue()).decode("utf-8")
    except Exception as e:
        logger.warning(f"Failed to downscale image, sending as-is: {e}")
        return b64_data
transformers.py — 정체성 역전 가드 데코레이터 
# 소형 로컬 모델이 가끔 고정된 관계 설정을 뒤집는다 - 캐릭터가
# 스스로를 "오빠"라 칭하거나("내가 너의 오빠야") 유저를 "여동생"이라
# 부르는 식. 둘 다 이 캐릭터 설정에서는 항상 틀린 말이라 오탐 걱정 없이
# 그대로 잡아내면 된다. 프롬프트만으로는 길고 지저분한 세션에서 안정적으로
# 지켜지지 않아서, TTS/화면 출력과 같은 단위인 완성된 문장 단위에서
# 결정론적으로 잡아내 안전한 대사로 치환한다.
IDENTITY_REVERSAL_RE = re.compile(
    r"(내가|나는|난)\s*(너의|당신의|니)?\s*오빠"
    r"|(너는|넌|너가|네가|당신은|당신이)\s*.{0,15}?여동생"
)
IDENTITY_GUARD_FALLBACKS = [
    "오빠잖아. 갑자기 왜 그래?",
    "오빠 맞잖아, 몰랐어?",
    "무슨 소리야, 오빠면서.",
]

def identity_guard():
    """sentence_divider 바로 뒤에 붙여, 토큰 조각이 아니라 완성된
    문장 단위로 검사한다."""
    def decorator(func):
        @wraps(func)
        async def wrapper(*args, **kwargs):
            stream = func(*args, **kwargs)
            async for item in stream:
                if isinstance(item, SentenceWithTags) and IDENTITY_REVERSAL_RE.search(item.text):
                    logger.warning(f"identity_guard caught reversed-identity sentence: {item.text!r}")
                    item.text = random.choice(IDENTITY_GUARD_FALLBACKS)
                yield item
        return wrapper
    return decorator
conversation_handler.py — 발화 다양성 엔진(직전 변형 제외 랜덤 추출) 
# random.choice만 쓰면 5개 중 1/5 확률로 직전과 같은 변형이 다시
# 뽑히는데, 실제로 그럴 때 모델이 거의 동일한 문장을 냈다(같은 맥락에
# 같은 지시라 그런 것으로 보임 - 연속 두 턴 모두 "엄마랑 같이…"로 시작).
# 직전 인덱스를 제외하고 뽑으면 이 반복을 원천 차단할 수 있다.
_last_proactive_variant_index: Dict[str, int] = {}

def _pick_proactive_variant(client_uid: str) -> str:
    last_index = _last_proactive_variant_index.get(client_uid)
    choices = range(len(PROACTIVE_SPEAK_VARIANTS))
    if last_index is not None:
        choices = [i for i in choices if i != last_index]
    index = random.choice(list(choices))
    _last_proactive_variant_index[client_uid] = index
    return PROACTIVE_SPEAK_VARIANTS[index]

한계 — 위 대응은 모두 확인된 실패 패턴에 대한 규칙 기반(정규식) 사후 교정입니다. Gemini 비교 실험에서 드러났듯, 근본 원인은 소형 로컬 모델 자체의 명령 이행 한계이므로 더 강한 모델이나 파인튜닝으로 대체하는 것이 정공법입니다. 이 작업은 지금 손에 있는 모델에서 실사용 품질을 끌어올리기 위한 엔지니어링에 가깝습니다.

느낀 점

작은 로컬 모델은 프롬프트를 아무리 다듬어도 일정 수준 이상 올라가지 않는다는 것을 Gemini와의 비교 실험으로 직접 확인했습니다. 그래서 이후 작업은 모델 자체를 바꾸는 대신, 반복해서 나타나는 실패 패턴(정체성 역전, 한자 혼입, 발화 반복)을 관찰하고 정규식·상태 관리로 사후 교정하는 쪽으로 방향을 잡았습니다. temperature를 올려 발화 다양성을 개선하려던 시도처럼 효과가 없던 방법은 데이터로 확인한 뒤 코드에 실험 기록만 남기고 되돌렸는데, 이 과정에서 "직관적으로 그럴듯한 개선안"과 "실제로 측정했을 때 효과가 있는 개선안"을 구분하는 습관을 얻었습니다.

문제 해결

능동 발화 기능에서 같은 상황에 2턴 연속 거의 동일한 문장이 나오는 문제가 있었습니다. 원인을 추적해보니 5가지 상황 변형 중 하나를 매번 새로 무작위 추출하다 보니 20% 확률로 직전 턴과 같은 변형이 다시 뽑히고, 같은 지시에는 모델이 같은 응답을 내놓기 때문이었습니다. 클라이언트별로 직전에 뽑힌 인덱스를 기억해두고 다음 추출에서 제외하는 방식으로 반복을 원천 차단했고, 이후 대화 로그에서 연속 반복이 사라진 것을 확인했습니다.
